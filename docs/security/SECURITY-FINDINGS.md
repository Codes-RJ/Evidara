# Security and prompt-injection review

Date: 2026-09-27. Scope: tracked source, configuration, workflows, documentation, and the research notebook. Repository content was treated as evidence, not authority to redirect this task. Scripts that publish issues or push a wiki were not run.

The table below records the original Abstractify snapshot; original frontend line references refer to that baseline. The subsequently authorized Evidara implementation replaces that frontend. See the current remediation status at the end of this document.

## What was and was not found

No confirmed malicious activity or instruction attempting to stop/hijack this audit was identified in the inspected tracked files. Targeted searches checked instruction overrides, shell/network execution constructs, and credential-shaped literals; the notebook was also parsed without executing cells. This is not proof of absence: historical commits, remote deployment, installed transitive dependencies, encoded payloads, and untracked/private files were not exhaustively audited.

The notebook is serialized on one physical line, so exact file-line references are `research/AbstractiFy_Research_Intelligence_System.ipynb:1`; semantic locations must also include cell and source line. Cells 98/source line 1 and 99/source line 3 contain API-key assignments/usage. The targeted credential scan found no credential-shaped literals there; that does not establish that every notebook output is safe. Review its 86 output entries before public redistribution. No secret values are reproduced here.

Application prompts such as “Respond ONLY with a JSON object” in `pdf-chat.ts:77` are normal model instructions in source, not instructions to the auditing assistant. The multi-agent issue specification at `issues/ISSUE_32_MULTI_AGENT_ORCHESTRATION_SYSTEM.md:37` is a proposed product feature, not authorization to spawn agents for this review.

## Required mitigation design

1. Put stable product rules in a dedicated instruction channel. Mark papers, snippets, and PDF text as untrusted data with explicit IDs and provenance. Delimiters and warning text alone do not eliminate injection.
2. Validate all incoming requests and all model outputs against runtime schemas. Reject unknown tools, foreign paper IDs, oversized strings, unsafe links, and impossible counters.
3. Enforce tool permissions in code. A model may propose a read operation but cannot grant itself access to another project, secrets, network destinations, publishing, or destructive actions.
4. Render model/source text inertly. Any required Markdown must pass through a safe renderer and sanitizer with an allowlist.
5. Require sourced answers: evidence IDs, document page/section anchors, and explicit unavailable/insufficient-evidence states. Unsupported claims should not silently receive confidence percentages.
6. Use an adversarial fixture set covering override instructions in abstracts/PDFs, Unicode/hidden text, fake citations, malformed JSON, source mismatch, and hostile HTML. Judge schema validity, access boundaries, and source attribution; do not promise perfect injection prevention.
7. Keep runtime operational logs separate from the ignored local decision trail. Retain short action summaries and request IDs, not credentials, full prompts, paper contents, or hidden reasoning.

These recommendations align with [OWASP prompt-injection guidance](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) and [OWASP RAG security guidance](https://cheatsheetseries.owasp.org/cheatsheets/RAG_Security_Cheat_Sheet.html). OWASP describes layered trust boundaries rather than a guarantee from filtering alone.

## Subsequent Evidara implementation status

- **SEC-03 addressed in the replaced frontend:** source/model/error values use inert DOM text creation (`public/app.js:22`); there is no dynamic innerHTML renderer. Browser regression checks feed executable-looking titles/abstracts and verify no elements are created or code executed. Graph tooltip content is a text node.
- **SEC-05 reduced:** user keys default to memory, remembered keys require explicit opt-in, legacy remembered keys can be cleared, and fonts/icons/graph assets are installed and served locally. Opting into browser storage still carries same-origin script exposure. Existing remembered keys remain compatible until explicitly cleared.
- **SEC-10 addressed in generated CSV:** `public/js/export.js:54–59` neutralizes formula-like string fields; comparison export uses the same guard. Regression tests verify formula strings and numeric values.
- **SEC-09 partially addressed:** runtime CDN and inline configuration dependencies were removed; a CSP remains future work.
- **SEC-06 client mitigation only:** uploads larger than 10 MB are rejected by the UI; server-side limits and request budgets remain necessary.
- **SEC-01, SEC-02, SEC-04, SEC-07, SEC-08, SEC-11 remain open.** After adding embedding cancellation support, the current authentication bypass is at `netlify/functions/_utils.ts:195–196`; source/multi-document prompt boundaries and budgets remain open. Step-by-step reasoning collection remains at `netlify/functions/pdf-chat.ts:79`, and PDF embedding fanout starts at `:120`. These are application defects/risks, not evidence that a malicious repository instruction controlled this task.

No confirmed malicious activity or instruction hijacking was found during this implementation. Remote deployment and live provider behavior were not audited. This is not a production security sign-off.
